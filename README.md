# Video RAG on TVBench

An experimental **Video Retrieval-Augmented Generation (Video RAG)** project using Qwen2.5-VL-3B-Instruct to answer questions about videos.

The goal was to investigate whether retrieving relevant temporal segments could improve video question answering compared with sampling a small number of frames from the entire video.

**Result:** The initial Video RAG implementation did not outperform the simpler baseline on the 20-question evaluation sample. This repository documents the implementation, experiments, results, and limitations.

## Overview

Video question answering requires more than recognizing objects in individual frames. Questions about movement, action counts, event timing, and action order require the model to interpret visual evidence over time.

This project explores whether a retrieval pipeline can help by splitting videos into smaller segments and selecting the most relevant segments for each question.

### What I built

- A baseline video question-answering system using six evenly sampled frames.
- A temporal chunking pipeline with two-second segments and one-second overlap.
- Automatic chunk descriptions generated by Qwen2.5-VL-3B-Instruct.
- Semantic embeddings using `sentence-transformers/all-MiniLM-L6-v2`.
- Cosine-similarity retrieval for selecting relevant video segments.
- A Video RAG pipeline that extracts frames from retrieved segments and generates answers.
- Evaluation scripts to compare the baseline and Video RAG approaches.

## Architecture

**Baseline**

```text
Video → Sample 6 frames → Qwen2.5-VL → Answer
```

**Video RAG**

```text
Video
  ↓
Overlapping temporal chunks
  ↓
Qwen-generated descriptions
  ↓
Semantic embeddings
  ↓
Retrieve top 3 chunks
  ↓
Extract relevant frames
  ↓
Qwen2.5-VL → Answer
```

The prototype generated **461 chunk descriptions across 18 unique videos** used in the evaluation sample.

## Evaluation Results

Both systems were evaluated on the same 20-question TVBench sample across four categories.

| Category | Six-frame baseline | Video RAG |
|---|---:|---:|
| Moving Direction — weighted score | 50.0% | 30.0% |
| Action Count — exact accuracy | 20.0% | 20.0% |
| Action Localization | Not scored | Not scored |
| Action Sequence — exact accuracy | 0.0% | 0.0% |
| **Overall weighted score** | **23.3%** | **16.7%** |

The overall scores exclude the five action-localization questions because numeric ground-truth intervals were unavailable in the saved evaluation results. The remaining 15 questions were scored using the project's evaluation rules.

These are results from a small evaluation sample, **not full-dataset TVBench benchmark scores**.

## Why Video RAG Fell Short

The added retrieval stage introduced new failure points instead of consistently improving the answers.

- **Imperfect chunk descriptions:** Qwen sometimes described objects or posture instead of the specific action. For example, it repeatedly described someone holding a laptop while missing the laptop-opening action.
- **Retrieval errors:** Semantically related descriptions were not always the most useful evidence for the question.
- **Limited temporal reasoning:** More sampled frames did not consistently improve action-sequence answers.
- **Redundant chunks:** Overlapping segments sometimes returned similar visual information rather than complementary evidence.
- **Prompt limitations:** A direction-focused prompt experiment did not improve the five-question direction test.

Semantic retrieval did work for a controlled query such as “What action involves drinking?”, retrieving chunks whose descriptions mentioned drinking. However, success on this example did not translate into better overall evaluation results.

## Key Takeaway

**More complex does not automatically mean better.**

The experiments suggest that imperfect descriptions, irrelevant retrieval, and limited temporal reasoning prevented the initial Video RAG system from improving on the baseline.

The project demonstrates a working Video RAG prototype and a reproducible baseline comparison, but the original performance-improvement goal was not achieved in this version.

## Project Structure

| File | Purpose |
|---|---|
| `12_run_evaluation.py` | Runs the baseline evaluation |
| `13_evaluate_results.py` | Scores baseline answers |

| `24_test_direction_prompt.py` | Tests a direction-focused prompt |

## Reproducing the Experiments

With the required dependencies, locally available models, evaluation videos, and generated chunk descriptions in place, run the baseline and RAG experiments:

```powershell
.\venv\Scripts\python.exe 12_run_evaluation.py
.\venv\Scripts\python.exe 13_evaluate_results.py
.\venv\Scripts\python.exe 22_run_rag_evaluation.py
.\venv\Scripts\python.exe 23_compare_baseline_vs_rag.py
```

The evaluation scripts save their results to JSON files, allowing the outputs to be inspected and compared.
